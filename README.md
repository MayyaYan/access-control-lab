# Практическая работа 1.2 Проверка контроля доступа веб-приложения

В этой работе вы запустите настоящий HTTP сервер, воспроизведёте две ошибки контроля доступа и проверите исправление. Все действия выполняются в вашем локальном стенде. Результат работы — заполненный отчёт с ответами сервера, снимками экрана и выводом автоматических тестов.

**Это учебное приложение с намеренными дефектами, а не действующая система колледжа.** Учётные записи и оценки — открытые учебные фикстуры. В отчёт нужно включить фактические результаты своего запуска. Сценарий соответствует реальной задаче тестировщика: проверить, что пользователь не читает чужие данные и не получает функции другой роли.

## Выполнить работу в браузере

[Открыть подготовленную облачную среду GitHub Codespaces](https://github.com/codespaces/new?hide_repo_select=true&repo=1401772366&skip_quickstart=true&ref=main)

Войдите в GitHub, нажмите Create codespace и дождитесь подготовки. Linux, Node.js и исходный код устанавливаются автоматически. Во вкладке Ports откройте порт **3000** — уязвимый стенд; порт **3001** — исправленный. Терминал доступен в браузере. Установка программ на компьютер не требуется.

У каждого студента собственная среда. Codespaces расходует ограниченную квоту аккаунта; после занятия остановите среду. Пошаговая инструкция: [docs/cloud-lab.md](docs/cloud-lab.md).

## Быстрый запуск

1. Установите Node.js версии 22 или новее с https://nodejs.org/ внутри виртуальной машины.
2. Скачайте ZIP репозитория, распакуйте его. Откройте терминал в папке, где находится `package.json`.
3. Проверьте установку командой `node --version`.
4. Запустите `npm run start:vulnerable`.
5. В браузере **внутри той же виртуальной машины** откройте http://127.0.0.1:3000.

Команда `npm install` не требуется: внешних зависимостей нет. После скачивания Node.js и репозитория работа может выполняться без интернета.

| Роль | Логин | Пароль | Работа |
| --- | --- | --- | --- |
| Студент А | `student-a` | `lab-a` | 101 |
| Студент Б | `student-b` | `lab-b` | 102 |
| Преподаватель | `teacher` | `lab-teacher` | 101 и 102 |

Войдите как `student-a`, укажите работу **102**, нажмите «Прочитать работу». В уязвимом режиме сервер отдаст чужую работу с HTTP 200. Нажмите «Список преподавателя» — обнаружите второй дефект.

Остановите сервер сочетанием Ctrl+C, затем запустите `npm run start:fixed`. Обновите страницу и войдите заново. Те же запросы должны вернуть HTTP 403.

## Виртуальная машина

Рекомендуемая конфигурация: VirtualBox или VMware, Windows 11 либо Ubuntu, 2 виртуальных процессора, 4 ГБ RAM, 25 ГБ диска, сетевой режим NAT. Если в учебной лаборатории уже используется Windows 10, команды стенда остаются теми же. Подготовка ОС и Node.js выполняется преподавателем до занятия; работа студента занимает 90 минут.

**NAT не заменяет проверку прав приложения.** Сервер специально слушает только `127.0.0.1` внутри гостевой ОС. Не настраивайте перенаправление портов: для задания оно не требуется. Это серверное приложение; GitHub Pages его не запускает. GitHub используется для хранения кода и автоматических тестов.

## Автоматические проверки

```text
npm test
npm run test:policy:vulnerable
npm run test:policy:fixed
```

`npm test` проверяет исправленную политику доступа и подтверждает, что намеренные дефекты воспроизводятся в уязвимом режиме: ожидается 17 успешных тестов.

`test:policy:vulnerable` проверяет уязвимый сервер по требованиям безопасного приложения: ожидаются **3 провала и 4 успеха**, код завершения 1. Провалы — доказательство дефектов, а не ошибка установки. `test:policy:fixed` повторяет те же 7 тестов: ожидается 7 успехов и код 0. Тесты поднимают свои временные локальные серверы и не используют запущенный вручную сервер на порту 3000.

При публикации GitHub Actions запустит тесты на Windows и Linux. Результаты появятся на вкладке Actions после первого push. Наличие workflow в коде само по себе не означает, что проверки GitHub уже прошли.

## Если не запускается

- `node` не найден: завершите установку Node.js и заново откройте терминал.
- PowerShell блокирует `npm.ps1`: используйте `npm.cmd` вместо `npm`, например `npm.cmd run start:vulnerable`, либо откройте cmd.exe.
- `EADDRINUSE`: остановите предыдущий сервер Ctrl+C. Для смены порта в PowerShell: `$env:PORT=3001`; в cmd.exe: `set PORT=3001`. Затем запустите сервер и откройте http://127.0.0.1:3001.
- `ENOENT package.json`: терминал открыт не в папке проекта. Перейдите в папку с `package.json` командой `cd`.
- После перезапуска требуется повторный вход: сеансы хранятся в памяти. Оценки также возвращаются к исходным значениям.
