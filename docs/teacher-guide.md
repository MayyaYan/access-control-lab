# Проверка отчёта преподавателем

## Ожидаемые результаты

До исправления student-a читает 102 с HTTP 200, student-b читает 101 с HTTP 200, студент открывает `/api/teacher/works` с HTTP 200. После исправления все три запроса возвращают 403. Собственные работы и функции преподавателя доступны в обоих режимах. Запросы без сеанса возвращают 401. Изменение оценки студентом запрещено в обоих режимах.

`test:policy:vulnerable`: 4 успешных и 3 проваленных теста, код завершения 1. `test:policy:fixed`: 7 успешных, 0 проваленных, код 0. `npm test`: 17 успешных, 0 проваленных. Проверки уязвимого поведения в общем наборе ожидают наличие дефекта и поэтому проходят; проверки политики требуют безопасного поведения и до исправления проваливаются.

## Оценивание

| Критерий | Баллы |
| --- | --- |
| Подготовленная ВМ, NAT, версия Node.js, запуск | 2 |
| Таблица ручных проверок и снимки с ролью и HTTP статусом | 3 |
| Объяснение IDOR, проверки роли и соответствующего кода | 2 |
| Фактические логи тестов до и после, корректная трактовка провалов | 2 |
| Вывод о результате и границах проверки | 1 |

9–10 баллов — оценка 5; 7–8 — оценка 4; 5–6 — оценка 3; 0–4 — оценка 2. Дополнительное задание используется для углубления, но не требуется для оценки 5.

Не принимать готовые ожидаемые результаты вместо наблюдений. Требовать совпадения таблицы, снимков и журналов. Проверка только собственной работы не доказывает безопасность контроля доступа. Успешные локальные тесты не подтверждают выполнение задания внутри ВМ: для этого нужны снимки гостевой ОС.
